Fragma IoT REST API

Dokumentasi resmi arsitektur REST API Fragma IoT. Platform ringan tanpa framework untuk menghubungkan mikrokontroler (ESP32, Arduino, Raspberry Pi), menyimpan data sensor, dan menampilkan visualisasi metrik secara asinkron.

1. Overview & Arsitektur

Fragma dirancang dengan prinsip kesederhanaan dan performa tinggi. Komunikasi antar-perangkat dan dashboard memanfaatkan standar HTTP/1.1 REST dengan pertukaran data berformat JSON murni (RFC 8259).

Base URL Lingkungan
Saat berjalan di Laragon Apache lokal:
http://fragma.test/api atau http://localhost/fragma/api

Konsep Inti Platform

  • Entity: Representasi logis dari satu perangkat IoT (memiliki ID unik, nama, API Key terisolasi, dan skema field).
  • Data Points: Baris telemetri yang dikirimkan perangkat ke database dengan penanda waktu (*timestamp*).
  • Widgets: Elemen visualisasi interaktif pada dashboard (Line Chart, Value Card, Gauge).

2. Autentikasi & Kunci API

Model autentikasi Fragma bersifat terisolasi per entitas (*per-entity API key*) tanpa keharusan membuat akun login yang rumit untuk perangkat mikrokontroler.

Format Kunci API
Prefix frag_ diikuti oleh 48 karakter heksadesimal acak (dihasilkan melalui fungsi kriptografi aman random_bytes(24)):
frag_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6

Kunci API dikirimkan melalui header HTTP X-API-Key:

HTTP Header 
X-API-Key: frag_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6

3. Telemetry Ingestion & Query API

Endpoint untuk pengiriman data telemetri dari mikrokontroler serta penarikan data ke antarmuka dashboard.

3.1. Push Telemetri Baru

POST /api/data.php?entity_id={entity_id}

Menyimpan data pembacaan sensor baru untuk entitas target. Wajib menyertakan header X-API-Key.

Parameter Tipe Posisi Keterangan
entity_id integer Query ID entitas penerima data.
X-API-Key string Header Kunci API entitas pemancar.
Payload Request (JSON) 
{
  "temperature": 27.8,
  "humidity": 62.4,
  "status": "nominal"
}

3.2. Query Riwayat Telemetri

GET /api/data.php?entity_id={entity_id}

Mengambil kumpulan riwayat telemetri. Bersifat publik untuk dashboard.

Parameter Query Tipe Default Keterangan
limit integer 100 Jumlah data maksimal yang dikembalikan (maks: 500).
range string - Filter rentang waktu (misal: 1h, 6h, 24h, 7d).
latest integer 0 Jika bernilai 1, mengembalikan hanya 1 data poin pembacaan paling akhir.

4. Entity Management API

Operasi CRUD untuk mengelola instans perangkat IoT.

GET /api/entities.php

Mengambil daftar seluruh entitas yang terdaftar beserta status konektivitasnya.

POST /api/entities.php

Mendaftarkan entitas baru. Body JSON berisi name dan array fields.

Contoh Body Pembuatan Entitas 
{
  "name": "Ruang Server Rack 1",
  "fields": [
    { "name": "temperature", "type": "number", "unit": "°C" },
    { "name": "humidity", "type": "number", "unit": "%" },
    { "name": "power", "type": "number", "unit": "W" }
  ]
}

5. Visual Widget Configuration API

Mengonfigurasi widget analitik pada visualizer dashboard.

POST /api/widgets.php?entity_id={entity_id}

Membuat widget baru dengan konfigurasi tipe (line-chart, value-card, atau gauge).

Body Penambahan Widget 
{
  "type": "line-chart",
  "config": {
    "field": "temperature",
    "label": "Rack Temperature Sensor",
    "color": "#4ecdc4",
    "unit": "°C",
    "variant": "area"
  }
}

7. PTS Release Candidate: REST API Integration

Sebagai pemenuhan rilis kandidat PTS, Fragma mengintegrasikan REST API publik live dan Mock Edge Gateway lokal menggunakan Fetch API, JSON, dan async/await.

7.1. REST API Publik (Open-Meteo Weather)

GET https://api.open-meteo.com/v1/forecast

Mengambil data atmosfer cuaca live stasiun terdekat tanpa autentikasi (WMO standardized). Digunakan untuk menghitung Delta HVAC (perbedaan suhu udara luar terhadap suhu rack server internal Fragma).

cURL Sintaks 
curl -s "https://api.open-meteo.com/v1/forecast?latitude=-6.2088&longitude=106.8456&current=temperature_2m,relative_humidity_2m,surface_pressure,wind_speed_10m,weather_code&timezone=Asia%2FJakarta"

8. Mock Edge Gateway Cluster API

Endpoint internal yang mereplikasi klaster sensor industri edge (Node Inflow, Exhaust, UPS Power, dan Chiller Flow). Endpoint ini menyediakan parameter deterministik untuk memvalidasi seluruh transisi state UI.

GET /api/gateway.php[?scenario=:scenario][&delay=:seconds]
Parameter Skenario Status HTTP Perilaku & Dampak UI State
scenario=normal 200 OK Mengembalikan 4 node telemetri operasional aktif (Success State).
scenario=empty 200 OK Mengembalikan array nodes: [] kosong (Empty State).
scenario=error 500 Error Mengembalikan struktur galat GATEWAY_CLUSTER_TIMEOUT (Error State).
scenario=delay / delay=2 200 OK Menambahkan jeda simulasi 2 detik untuk mengamati Loading State.

9. UI State Lifecycle Matrix

Setiap interaksi Fetch asinkron dikelola melalui 4 state visual yang mematuhi prinsip desain *antislop*:

State Antarmuka Kondisi Pemicu Representasi Visual Aksi Pemulihan
Loading fetch() sedang aktif berjalan. Skeleton loader beranimasi shimmer, status chip kuning Memuat.... Otomatis terselesaikan saat Promise selesai.
Success HTTP 200 dengan payload valid. Kartu telemetri interaktif, latensi ms, korelasi HVAC, inspeksi Raw JSON. Tombol 'Sinkronkan REST API' untuk refresh manual.
Empty HTTP 200 dengan nodes: [] kosong. Kontainer kosong ramah pengguna dengan ikon SVG minimalis (tanpa emoji). Tombol 'Muat Data Default' & 'Beralih ke Open-Meteo'.
Error HTTP 500 atau jaringan terputus. Kontainer merah terukur dengan kode status, blok diagnostik, dan saran tindakan. Tombol 'Coba Hubungi Kembali (Retry)' & Opsi Fallback.

10. Contoh Integrasi Perangkat

10.1. ESP32 (Arduino C++)

ESP32_Telemetry_Sender.ino 
#include <WiFi.h>
#include <HTTPClient.h>

const char* ssid = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASSWORD";
const char* serverUrl = "http://fragma.test/api/data.php?entity_id=1";
const char* apiKey = "frag_a1b2c3d4e5f6...";

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
  }
}

void loop() {
  if (WiFi.status() == WL_CONNECTED) {
    HTTPClient http;
    http.begin(serverUrl);
    http.addHeader("Content-Type", "application/json");
    http.addHeader("X-API-Key", apiKey);
    
    String payload = "{\"temperature\": 27.4, \"humidity\": 61.2}";
    int httpResponseCode = http.POST(payload);
    http.end();
  }
  delay(10000);
}

10.2. Python 3

sensor_push.py 
import requests

url = "http://fragma.test/api/data.php?entity_id=1"
headers = {
    "Content-Type": "application/json",
    "X-API-Key": "frag_a1b2c3d4e5f6..."
}
payload = {
    "temperature": 26.8,
    "humidity": 59.5
}

response = requests.post(url, json=payload, headers=headers)
print(response.status_code, response.json())

11. HTTP Status & Error Handling

Kode Status Artinya Deskripsi Penanganan
200 OK Sukses Permintaan berhasil diproses dan dikembalikan.
201 Created Berhasil Dibuat Entitas atau data point baru berhasil tersimpan.
400 Bad Request Payload Tidak Valid Field wajib hilang atau JSON tidak dapat di-parse.
401 Unauthorized Kunci API Salah Header X-API-Key tidak sesuai dengan entitas target.
404 Not Found Tidak Ditemukan Entitas atau widget dengan ID target tidak ada.
500 Server Error Galat Internal Masalah pada koneksi database atau timeout gateway cluster.
